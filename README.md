# ReleaseFlow

Курсовой проект: веб-приложение учёта задач и релизов разработки. Кубарев Егор, РИЗ-250938У, УрФУ, 2026.

## Запуск

Нужны JDK 17+ и Maven 3.9+ (либо Maven Wrapper; при первом запуске нужен интернет).

```sh
./mvnw verify
java -jar target/releaseflow-0.0.1-SNAPSHOT.jar --spring.profiles.active=demo
```

Открыть http://localhost:8081. Приложение слушает только 127.0.0.1. Для другого порта: `PORT=8082 java -jar ...`.
Запускать из корня проекта: относительные пути базы и журнала зависят от рабочего каталога.

## Демонстрационные аккаунты

Профиль `demo` заполняет только пустую базу. Общий учебный пароль: `ReleaseDemo!2026`.

| Логин | Доступ |
|---|---|
| admin | ADMIN, все записи, управление ролями и Actuator |
| egor | USER, только свои задачи и релизы |
| anna | USER, отдельная область данных |
| viewer | READ_ONLY, просмотр общих списков, без изменения |

Самостоятельная регистрация всегда назначает READ_ONLY. Затем администратор открывает «Пользователи и роли» и назначает USER или ADMIN. Изменение начинает действовать со следующего запроса. Самому себе снять ADMIN нельзя.

Без `--spring.profiles.active=demo` тестовые пользователи не создаются. Для первоначальной локальной демонстрации используйте demo на пустой базе; уже существующая непустая база не дополняется. Профиль demo и опубликованные учебные пароли предназначены для локальной защиты проекта.

## Возможности

- Регистрация, вход, выход, BCrypt, CSRF, серверная валидация.
- CRUD задач и релизов, фильтры поиска/статуса/релиза, доска состояний.
- Проверка владельца на сервере; защита от подстановки чужого id и owner. Новая задача принадлежит создателю; форма предлагает его релизы. ADMIN может изменять чужие задачи в пределах релизов того же владельца.
- Версия записи (`@Version`), отказ устаревшему обновлению 409.
- Запрет удаления релиза с задачами; задачи и релиз имеют одного владельца.
- Расчёт бюджета с резервом, готовности по трудозатратам и даты окончания.
- Журнал в USER_ACTIONS и logs/releaseflow.log; последние 200 событий в UI.
- /actuator, /actuator/health, /actuator/info, /actuator/metrics и /actuator/mappings доступны ADMIN.

READ_ONLY по заданию читает общие списки; USER ограничен своими записями, ADMIN видит все. READ_ONLY может выполнить расчёт, который не изменяет задачи и релизы. Все роли видят только собственный журнал, кроме ADMIN.

## Расчёт

Стоимость задачи = человеко-дни × дневная ставка, округление HALF_UP до копеек. Бюджет = сумма стоимостей × (1 + резерв / 100). Готовность = трудозатраты завершённых задач / все трудозатраты. Остаток делится на участников с округлением вверх. Дата строится по будним дням после даты начала; суббота и воскресенье пропускаются. Праздники, зависимости и разная производительность не моделируются.

Для v1.0 при 2 участниках, резерве 15% и начале 28.10.2026: 10 человеко-дней, остаток 7, база 108000.00 ₽, бюджет 124200.00 ₽, готовность 30%, дата 03.11.2026. Это оценка, а не договорный срок.

## База и журналы

H2 2.3.232, URL `jdbc:h2:file:./testdb/releaseflow`, sa, пустой пароль локальной базы. Хеши веб-паролей хранятся в USERS. База, журналы и target исключены из Git. Останавливайте приложение перед подключением DBeaver Embedded и перед копированием файла БД. SQL проверки: evidence/verification.sql. Переменная DB_URL меняет путь базы.

Файловый лог ротируется по 5 МБ, история до 7 архивов. Бизнес-операция и запись аудита в БД входят в одну транзакцию. Файл не является транзакционным хранилищем; при откате после записи сообщения возможны расхождения. Для промышленной доставки аудита нужен outbox.

## Ограничения

Учебный монолит без внешних интеграций, уведомлений, восстановления паролей, производственного календаря и нагрузочного тестирования. Списки не имеют пагинации; фильтры применяются к доступному набору в памяти. `ddl-auto=update` удобен для демонстрации; развитие схемы требует Flyway/Liquibase. Рабочие версии зафиксированы в pom.xml и не обозначены как самые новые. Перед внешним развёртыванием нужны обновление зависимостей, HTTPS, отдельная серверная БД, секреты окружения и отдельная процедура создания первого администратора.
